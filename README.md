# 상식 한 바퀴

한국사·과학·지리·예술과 문화의 사전 검수 문제로 진행하는 한국어 4지선다 상식 퀴즈입니다. 로그인과 서버 데이터베이스 없이 PC 브라우저에서 로컬 실행합니다. 모바일 크기의 화면에도 대응합니다.

## 처음 실행하기 — Windows

1. [Node.js 공식 다운로드](https://nodejs.org/en/download)에서 **Node.js 24 LTS의 최신 24.x 버전(24.15.0 이상)**을 설치합니다. Windows용 `.msi` 설치 프로그램을 선택하고, 설치 후 열려 있던 CMD 창은 닫았다가 다시 엽니다. npm은 함께 설치됩니다.
2. 이 프로젝트 ZIP을 다운로드하고 **모두 압축 풀기**를 선택합니다. 이전에 받은 문제 자료만 담긴 ZIP은 별도로 옮기거나 합칠 필요가 없습니다. 이 프로젝트에 재검수한 문제와 문서가 이미 들어 있습니다.
3. 압축을 푼 **knowledge-quiz 폴더**를 엽니다. `package.json`, `package-lock.json`, `src`가 보이는 폴더가 맞습니다. 폴더를 옮기고 싶다면 사용자 폴더 아래 `Projects` 같은 곳에 보관합니다.
4. 파일 탐색기의 **주소창**을 클릭해 `cmd`를 입력하고 Enter를 누릅니다. 해당 폴더에서 명령 프롬프트가 열립니다.
5. 아래 명령을 한 줄씩 실행합니다. 처음 `npm ci`를 실행할 때는 인터넷이 필요합니다.

```bat
node --version
npm --version
npm ci
npm run dev
```

6. 마지막 명령이 실행 중인 상태에서 브라우저에 **http://127.0.0.1:5173/** 을 입력합니다. CMD 창을 닫으면 로컬 서버도 종료됩니다. 종료하려면 CMD에서 `Ctrl+C`를 누릅니다. Windows가 일괄 작업 종료 여부를 물으면 `Y`를 입력합니다.

`index.html`을 직접 더블클릭하는 방식은 사용하지 않습니다. 이 채팅의 실행 환경은 사용자 PC와 다른 컴퓨터이므로, 사용자 PC에서는 위 절차로 실행해야 합니다. 프로젝트는 외부 공개 배포하지 않았습니다.

## 다음부터 실행하기

같은 프로젝트 폴더의 주소창에서 `cmd`를 열고 아래만 실행합니다.

```bat
npm run dev
```

같은 브라우저·프로필에서 **http://127.0.0.1:5173/** 으로 접속합니다. `localhost`, 다른 포트, 다른 브라우저는 서로 다른 기록 저장소로 취급될 수 있습니다. 포트 5173이 이미 사용 중이면 자동으로 다른 주소로 바꾸지 않고 오류를 표시합니다. 이전에 열어 둔 이 프로젝트 CMD에서 Ctrl+C로 종료한 뒤 재실행해 주세요.

프로젝트의 의존성 파일이 바뀌거나 `node_modules`를 삭제한 경우에만 `npm ci`를 다시 실행합니다. 앱 파일을 수정하면 개발 서버가 반영하며, 상황에 따라 화면이 새로고침되어 진행 중 게임이 초기화될 수 있습니다.

## 게임 사용 순서

1. 닉네임을 입력합니다. 모든 공백은 자동 제거되며 NFC 정규화 후 유니코드 코드 포인트 1~12자로 제한합니다. 일부 이모지는 여러 코드 포인트로 계산될 수 있습니다.
2. 퀴즈 시작하기를 누르면 네 분야에서 각각 3문제씩 총 12문제를 뽑습니다. 같은 게임에서는 중복이 없고 문제·보기 순서는 무작위입니다.
3. 보기 하나를 선택하고 답 제출하기를 누릅니다. 선택 전에는 제출할 수 없습니다. 정답은 10점, 오답은 0점입니다.
4. 채점 후 정답 여부, 올바른 답, 해설, 출처를 확인합니다. 출처 링크는 새 창으로 열리며 인터넷이 필요합니다. 제출한 답은 바꿀 수 없습니다.
5. 다음 문제를 직접 눌러 진행합니다. 마지막 해설 뒤 결과 보기를 누르면 총점·정답 수·분야별 결과·저장 여부·순위가 나옵니다. 시간 제한은 없습니다.
6. 다시 하기를 누르면 이전 게임 상태를 초기화하고 시작 화면으로 돌아갑니다. 완료 기록은 남습니다. 같은 닉네임으로 여러 번 완료하면 각각 별개의 기록입니다.

키보드는 Tab으로 이동하고, 라디오 보기에서는 방향키 또는 Space로 선택할 수 있습니다. 제출 버튼에 포커스를 둔 뒤 Enter로 제출합니다. 새 문제와 피드백으로 포커스가 이동하며 정답·오답은 텍스트와 색상으로 함께 표시합니다. 삭제 확인 창은 Escape로 취소할 수 있습니다.

## 점수·순위 저장

- `localStorage`의 `knowledge-quiz:completed:v1:<게임 ID>` 키에 완료 게임별로 저장합니다. 서버로 전송하지 않습니다. 완료 ID·닉네임·점수·정답 수·분야별 결과·완료 시각·문제 은행 버전을 포함합니다.
- 새로고침·브라우저 재시작 후에도 같은 브라우저 프로필과 실행 주소의 기록을 읽습니다. 진행 중 게임은 메모리에만 있어 새로고침하면 초기화됩니다. 미완료 게임은 저장하지 않습니다.
- 점수 내림차순이며 같은 점수는 **1위, 1위, 3위** 방식입니다. 동점 내에서는 완료 시각 오름차순, 시각도 같으면 ID순으로 표시합니다. 시각은 UTC로 저장하고 기기 현지 시각으로 표시합니다.
- 은행 버전별로 별도 순위를 계산합니다. 결과 화면은 완료 당시 버전 기준이며 순위 화면의 버전 선택에서 과거 버전을 볼 수 있습니다.
- 기록 저장에 실패하면 성공으로 표시하지 않고 재시도 버튼을 제공합니다. 저장 성공을 확인하지 못하면 결과 화면에서 순위를 확정하지 않습니다.
- 손상되었거나 지원하지 않는 형식의 기록은 순위에서 제외하고 안내합니다. 원본은 자동 삭제하지 않습니다. 삭제 확인 후에는 이 앱의 모든 버전 완료 기록만 삭제합니다.
- 브라우저 데이터 삭제, 저장 공간 정리, 시크릿 창 종료, 사용자 설정 등에 따라 기록이 사라지거나 저장이 차단될 수 있습니다. 자동 백업·복구 기능은 없습니다.
- 순위는 이 브라우저의 기록 기준입니다. 다른 사용자·기기와 통합 순위를 공유하려면 공통 저장소와 사용자 구분 등 추가 개발이 필요합니다. 현재 앱에는 포함되어 있지 않습니다.
- 로컬 기록과 기기 시계는 사용자가 수정할 수 있으므로 조작 방지 기능을 갖춘 공식 대회 순위가 아닙니다.

## 문제 은행과 콘텐츠 검증

현재 은행 버전은 **1.1.2**, 총 **200문제(분야별 50문제)**입니다. 기존 40문제에 160문제를 추가했고, 1.1.1에서 전체 200문제와 연결된 출처 URL 130개를 다시 열어 대조했습니다. 1.1.2에서는 외부 검수 의견을 원문·코드에 대조해 검색 안내와 질문 2개를 다듬었습니다. 한 게임은 분야별 3개씩 총 12문제입니다. 최신 반영 내역과 Git 등록 전 검사 범위는 `docs/PRE-GIT-REVIEW.md`, 전체 재검수는 `docs/REREVIEW-1.1.1.md`, 확장 당시 기록은 `docs/EXPANSION-1.1.0.md`입니다.

앱이 읽는 파일은 `src/data/question-bank.json`입니다. 새 문제의 기본 상태는 `확인 필요`이며 원문 확인·재검수를 마친 `검증 완료` 문제와 3단계 승인 기록이 있는 문제만 출제합니다. 어떤 분야라도 3개 미만이거나 은행 인계 승인이 없으면 시작을 막습니다. 일부 잘못된 문제는 제외한 뒤 사유를 표시합니다.

기관 원문을 열어 정답·오답·조건·해설을 대조했고 별도 단계에서 다시 검수했습니다. 검색 요약만으로 검증하지 않았으며 원문 접근에 실패한 자료는 최종 증빙으로 사용하지 않았습니다. 자료와 검수 내역은 다음 파일에 있습니다.

- `docs/question-bank.md`: 현재 전체 200문제·정답·해설·출처. 오답별 판단은 문제 JSON의 review.distractors에 있습니다.
- `docs/question-bank.html`: 브라우저에서 설치 없이 읽는 현재 전체 목록. 출처 원문 검색어도 표시합니다.
- `docs/REREVIEW-1.1.1.md`, `docs/review-matrix-1.1.1.json`, `docs/rereview-changes-1.1.1.json`: 최신 전체 재검수 결과와 문항별 수정 전후.
- `docs/EXPANSION-1.1.0.md`, `docs/review-matrix-1.1.0.json`: 추가 160문제의 검수·수정·제외 내역과 문항별 근거.
- `docs/review-stage3.md`, `docs/review-matrix-stage3.md`: 초기 40문제의 재검수 결과와 문항별 판단.
- `docs/review-stage2.md`, `docs/changes-stage3.json`: 제작·수정 이력. 과거 단계의 미완료 표시는 당시 기록입니다.
- `docs/CONTENT-GUIDE.md`: 새 문제 작성·검수·승인·은행 버전 변경 방법.

게임 실행 중 AI 호출, 문제 생성, 실시간 사실 검색은 하지 않습니다. 출처는 사용자가 링크를 누를 때만 별도 사이트로 엽니다. 자동 데이터 검사만으로 사실의 진실성이 증명되지는 않습니다. 같은 AI 도우미가 재검수했으며 외부 전문가나 다른 사람의 독립 검수는 받지 않았습니다. 실제 이용자 정답률에 따른 난이도 보정도 하지 않았습니다. 사실 오류가 절대로 없다고 보장하지 않습니다.

## 전체 문제를 확인하는 방법

게임을 여러 번 풀지 않아도 전체 목록을 볼 수 있습니다.

1. 최신 ZIP을 다운로드한 뒤 Windows의 **모두 압축 풀기**로 풉니다.
2. `knowledge-quiz` → `docs` 폴더로 들어갑니다.
3. **question-bank.html**을 더블클릭합니다. Chrome 또는 Edge로 열면 됩니다. 이 문서를 보는 데에는 Node.js 설치나 로컬 서버 실행이 필요 없습니다.
4. 상단의 분야 이름을 눌러 이동하고, **Ctrl+F**로 `hist-023`, `혈소판`, `카르멘`처럼 문제 ID나 단어를 검색합니다.
5. 각 문제의 보기 4개 → 정답 → 해설 → 출처 순서로 읽습니다. 출처를 누르면 기관 원문이 새 탭으로 열립니다. 외국어 원문에서는 표시된 **원문 검색어**를 복사하고 그 탭에서 Ctrl+F로 찾습니다. 이때만 인터넷이 필요합니다.

메모장이나 VS Code로 `docs/question-bank.md`를 열어도 같은 전체 목록이 있습니다. 앱의 실제 데이터와 세 오답의 검수 근거는 `src/data/question-bank.json`입니다. 확인만 할 때에는 이 JSON을 수정하지 않아도 됩니다.

게임 안에서는 답 제출 직후 해당 문제의 정답·해설·출처를 확인할 수 있습니다. 한 게임은 무작위 12문제이므로 전체 검수에는 위 문서를 사용하세요.

문제 JSON을 직접 수정한 뒤에는 검수·승인을 먼저 하고 읽기용 문서를 다시 생성합니다. 다음 명령은 JSON을 문서로 옮길 뿐 사실을 검증하거나 승인하지 않습니다.

```bat
npm run export:questions
```

현재 자동 검증 결과와 실제 브라우저 미실행 항목은 `docs/TEST-REPORT.md`, 직접 확인 방법은 `docs/MANUAL-CHECKLIST.md`에 있습니다. 개발 중 실제 Node.js 환경에서 자동 검사와 빌드는 실행했지만 Windows CMD, 실제 PC/모바일 브라우저의 시각적 배치와 재시작 동작은 이 환경에서 직접 확인하지 못했습니다.

## Git에 올리기

ZIP 파일 자체를 올리는 대신 압축을 푼 프로젝트의 개별 파일을 Git으로 관리합니다. `node_modules`, `dist`, 테스트 결과, 환경 파일은 `.gitignore`로 제외합니다. `package.json`과 `package-lock.json`, 문제 데이터와 검수 문서, 소스와 테스트는 포함합니다. 개인 닉네임·점수 기록은 브라우저에 있어 저장소에 포함되지 않습니다.

Git 설치 후, GitHub에서 파일이 없는 빈 저장소를 만든 다음 프로젝트 폴더 CMD에서 실행합니다. `YOUR_ACCOUNT`와 `YOUR_REPOSITORY`를 실제 계정·저장소 이름으로 바꿉니다. 이미 Git으로 관리 중이면 init·remote 설정을 반복하지 않습니다.

```bat
git init -b main
git add .
git commit -m "Build Korean knowledge quiz with reviewed question bank"
git remote add origin https://github.com/YOUR_ACCOUNT/YOUR_REPOSITORY.git
git push -u origin main
```

Git이 작성자 이름·이메일 설정을 요청하면 본인이 사용할 정보를 설정한 뒤 커밋을 다시 실행합니다. GitHub 인증은 본인 계정으로 진행합니다. 실제 저장소 주소를 정하면 그 주소에 맞춘 명령으로 안내할 수 있습니다. 현재 원격 저장소 연결이나 push는 수행하지 않았습니다.

수정 후에는 다음처럼 진행합니다.

```bat
npm run check
git status
git add .
git commit -m "Describe the change"
git push
```

GitHub 업로드와 웹 공개 배포는 서로 다릅니다. 이 프로젝트에는 자동 공개 배포를 설정하지 않았습니다.

src/

  logic/content.ts           검증 상태 검사·출제·섞기
  logic/game.ts              선택·제출·진행·점수
  logic/records.ts           기록 검사·저장·삭제·공동 순위
  logic/types.ts             데이터 타입·닉네임 규칙
  components/ConfirmDialog.tsx
  App.tsx                    시작·문제·채점·결과·순위 화면
  styles.css                 PC·모바일 스타일
scripts/
  validate-bank.mjs           데이터 구조 검사
