# 문제 은행 확장·재검수 — 1.1.0

확인일: 2026-10-17. 이전 1.0.0의 40문제에 160문제를 추가하여 총 200문제로 확장했다. 한 게임은 계속 분야별 3개씩 12문제이다.

## 출제 가능 수량

| 분야 | 기존 | 추가 | 검수 후 출제 가능 |
| --- | ---: | ---: | ---: |

신규 ID는 각 분야의 011~050이다. 기존 001~010의 질문·보기·정답·해설은 유지했다. 과거 40문제 제작·검수 문서는 당시 이력이며, 현재 전체 목록은 `question-bank.md`와 앱의 `src/data/question-bank.json`이다.

## 실제 수행한 콘텐츠 검증

1. 웹 검색과 기관 원문 열람으로 후보를 골랐다. 신규 문항에 사용한 원문은 서로 다른 URL 기준 88개이다. 국사편찬위원회, NASA, NIH, BIPM, 텍사스대학교 오스틴, UNESCO 세계유산센터, 공식 미술관·공연기관·정부 문화 안내 자료를 사용했다.
2. 검색 결과의 짧은 요약으로 판정을 끝내지 않았다. 원문에서 핵심 사실이 있는 문단·표·작품 정보란을 읽고, 해설을 그 범위로 제한했다. 원문 긴 문장과 이미지 복제는 하지 않았다.
3. 신규 160문제의 원문 88개를 별도 단계에서 다시 열었다. 긴 페이지의 본문이 잘려 나오면 해당 위치를 추가 열람했다. 원문 내용과 질문·정답·조건·해설의 의미를 대조했다.
4. 오답 세 개는 정답을 특정하는 관계·정의·작품 정보를 기준으로 배제하고, 동의어·포함 관계·부분적으로 맞는 답이 생기지 않는지 검토했다. 오답마다 별도 문서를 확보한 것은 아니다. 배제 판단은 같은 AI 도우미의 편집 검토이다.
5. 기존 문제까지 포함한 200문제에서 동일 질문·동일 핵심 관계의 중복, 해설을 통한 다른 문제의 답 노출, 조건 누락, 보기 길이·문체 단서를 검토했다. 같은 인물·장소가 다른 사실의 정답으로 재등장하는 경우는 있다. 건국자와 건국 연도처럼 같은 주제의 서로 다른 사실은 남기되, 해설이 서로의 정답을 직접 알려 주지 않도록 했다.
6. 원문 재열람 후 구조·필수 필드·정답 ID 연결을 프로그램으로 검사했다. 키워드 대응과 필드 검사는 근거 위치 추적용이며 의미·진실성을 자동 증명하지 않는다.

개별 신규 문항의 원문·재열람 위치·오답 ID·검토 항목은 `review-matrix-1.1.0.json`에 기록했다. 웹 도구 참조 문자열은 작업 추적용이며 영구 문서 주소가 아니다. 실제 출처 URL은 별도로 저장했다. 오답별 판단은 문제 JSON의 `review.distractors`에 있다.

## 보류·제외한 후보와 자료

- 강강술래·탈춤·연등회·대목장·남사당놀이·줄타기의 UNESCO 무형유산 개별 페이지는 이번 열람에서 접근 차단 안내만 표시되었다. 해당 페이지의 검색 요약은 최종 근거로 쓰지 않았다. 포함된 관련 문항은 실제 열린 한국관광공사·한국문화원 안내 자료로 검증했다. 연등회 후보는 이번 추가분에 포함하지 않았다.
- MoMA의 「아비뇽의 처녀들」·「브로드웨이 부기우기」 후보는 이번 원문 열람에 실패하여 추가하지 않았다. 확인한 기관의 다른 작품으로 구성했다.
- 내셔널 갤러리의 「로커비 비너스」 후보 URL은 열람 실패로 제외했다. 확인하지 않은 주소를 출처로 싣지 않았다.
- 카네기홀 자료를 사용하려던 「피터와 늑대」·「동물의 사육제」 후보도 원문 열람에 실패하여 추가하지 않았다.
- 장보고 사망 연도는 원문에 전하는 기록 차이가 있어 묻지 않았다. 활동 인물과 청해진 위치만 사용했다.
- 현재 인구·알려진 위성 수·관람 일정·문화유산 등재 수처럼 달라질 수 있는 수치, 논쟁적 최대·최초 주장은 신규 질문에서 제외했다. 천문 질문의 가장 가까운 행성 등은 범위가 명확하고 안정적인 비교로 한정했다.

## 버전과 사용법

- 은행 버전은 `1.1.0`이다. 앱 프로그램 버전과 은행 버전은 별도이며 앱 패키지 버전은 1.0.0으로 유지했다.
- 1.0.0 완료 기록을 삭제하거나 1.1.0 순위에 합치지 않는다. 같은 브라우저·프로필·주소를 유지하면 순위 화면의 버전 선택으로 과거 기록을 볼 수 있다.
- 최신 ZIP은 전체 프로젝트이다. 새 폴더에 압축을 풀고 README의 Windows 실행 절차를 따른다. 기존 프로젝트를 Git으로 관리 중이면 `.git` 폴더를 보존하고 최신 소스와 문서를 반영한 뒤 `git diff`, `npm run check`로 변경을 확인한다. 개인 수정 파일이 있다면 덮어쓰기 전에 보관한다.
- 완료 기록은 프로젝트 폴더 안에 없고 브라우저에 있다. 폴더를 바꾸더라도 같은 실행 주소를 사용해야 기존 기록을 읽는다.

## 확인하지 못한 사항과 한계

- 같은 AI 도우미가 작성과 별도 재검수를 수행했다. 외부 전문가·다른 사람의 독립 검수는 수행하지 않았다. 사실 오류가 전혀 없음을 보장하지 않는다.
- 중학생~성인 초보자를 기준으로 편집했으나 실제 사용자 정답률로 난이도를 측정하지 않았다. 분야별 난이도가 완전히 같다고 보장하지 않는다.
- 원문은 확인 시점에 열렸다. 기관의 사이트 변경·접근 정책·문서 수정으로 향후 링크가 달라질 수 있다.
- 실제 PC·모바일 브라우저의 시각적 배치, Windows 실행, 브라우저 완전 종료 후 저장 유지 검사는 미실행이다. `TEST-REPORT.md`와 `MANUAL-CHECKLIST.md`에 범위와 직접 확인 방법을 분리했다.
